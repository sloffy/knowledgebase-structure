# База знаний по водным видам спорта

Локальный дэшборд для наполнения, проверки и поиска знаний о SUP, каякинге, виндсёрфинге и других водных видах спорта. Предназначен для дальнейшего развития экосистемы Go-Spot; интеграция с go-spot.ru не добавлена.

Java 21, Spring Boot 4.1.1, Maven, Spring Data JPA, PostgreSQL 17. Интерфейс — HTML/CSS/JavaScript без внешних библиотек и сборки фронтенда.

## Что умеет

- Поиск по вопросу и явным фильтрам: темы, категории, опыт, вода, ветер и числовые параметры.
- Выдача по основной теме, дополнительным темам утверждения и связям между темами на один шаг.
- Создание и редактирование утверждений, источников, тем и синонимов; создание связей.
- Категориальные условия и диапазоны скорости ветра, температуры воды/воздуха, высоты волн.
- Проверка утверждений с именем проверяющего, временем, комментарием и историей решений.
- Постраничные результаты и объяснение, почему запись найдена и какие ограничения остаются неизвестными.
- Защита утверждений от сохранения и проверки по устаревшей версии.

## Запуск

Нужны JDK 21, Maven 3.9+ и запущенный Docker Desktop в режиме Linux-контейнеров.

Из корня проекта выполните три команды. Настройки уже находятся в `.env`, задавать переменные в PowerShell не нужно:

```powershell
docker compose up -d
mvn verify
java -jar target/structure-0.0.1-SNAPSHOT.jar
```

Откройте **http://localhost:8080** или **http://127.0.0.1:8080**.

Docker Compose автоматически читает `.env`; Spring Boot читает этот же файл через `spring.config.import`. В нём уже заданы пользователь `water_knowledge`, локальный пароль `root`, порт PostgreSQL `5433` и порт дэшборда `8080`. При необходимости измените файл один раз — эти значения будут использоваться при следующих запусках. Адрес подключения к БД собирается автоматически, поэтому при смене `DB_PORT` отдельно менять `DB_URL` не нужно.

`.env` исключён из Git. Без `.env` используются такие же локальные значения по умолчанию. Для своих настроек создайте `.env` в корне проекта и пишите значения в формате `KEY=value`, без кавычек и `export`. Переменные окружения и параметры командной строки по-прежнему позволяют переопределять настройки.

Приложение по умолчанию слушает только `127.0.0.1`. Это локальный редактор без авторизации; для общего доступа потребуется отдельная аутентификация.

Если порт БД занят, измените `DB_PORT` в `.env` и снова выполните `docker compose up -d`. Порт дэшборда меняется через `PORT` в том же файле. Изменение пароля в `.env` не меняет пароль уже созданной PostgreSQL: для существующей базы нужно использовать её текущий пароль или отдельно сменить пароль пользователя, сохранив данные.

Для завершения приложения нажмите Ctrl+C; `docker compose down` останавливает базу, сохраняя данные в Docker-томе.

### Работа с дэшбордом

1. В «Темах и связях» создайте тему и её синонимы. Свяжите вид спорта со снаряжением или средой.
2. В «Источниках» добавьте название, адрес документа, автора/организацию и даты. Адрес может быть ссылкой или идентификатором локального документа.
3. Нажмите «Добавить знание»: укажите тему, категорию, текст, дополнительные темы, условия и подтверждающие фрагменты.
4. Обычная новая запись имеет статус `CANDIDATE`. Откройте очередь «На проверке», укажите проверяющего, комментарий и решение.
5. Проверьте выдачу в «Поиске знаний». Кандидаты и отклонённые записи не выдаются; учебные записи включаются отдельным переключателем.

Для `VERIFIED` необходимо хотя бы одно подтверждение из неучебного источника. Имя проверяющего вводится вручную: пока это не авторизованная учётная запись. Проверка фиксирует решение редактора, автоматически достоверность документа не устанавливается.

После редактирования `VERIFIED` или `REJECTED` запись возвращается в `CANDIDATE`, текущая отметка проверки сбрасывается, история сохраняется. Условия и подтверждения тоже считаются частью редактирования. Учебный признак утверждения и источника нельзя переключить при правке; учебные утверждения не проходят проверку. Адрес уже цитируемого источника защищён от замены: для другого документа создайте новый источник.

### Консоль

```powershell
java -jar target/structure-0.0.1-SNAPSHOT.jar --spring.profiles.active=console
```

Команды завершения: `exit` / `выход`; EOF также завершает работу. Интерактивный ввод использует кодировку терминала, перенаправленный — UTF-8. Консоль сохраняет прежний режим: одна приоритетная категория, общие сведения при неизвестной категории, до пяти результатов.

## Модель хранения

| Сущность | Назначение |
| --- | --- |
| `Topic`, `TopicSynonym` | Темы SPORT/EQUIPMENT/ENVIRONMENT и варианты названий |
| `TopicRelation` | Направленные отношения USES/DEPENDS_ON/PRACTICED_ON |
| `Statement` | Утверждение, основная и дополнительные темы, категория, статус, последняя проверка |
| `StatementCondition` | Тип и описание ограничения, числовые границы и единица измерения |
| `Source` | Документ, учебный признак, автор, даты публикации и обращения |
| `Evidence` | Источник, подтверждающий фрагмент и позиция в документе |
| `StatementReview` | Неизменяемая история решений с автором, временем и комментарием |

Идентификаторы — строковые ключи до 120 символов. Новые записи получают UUID; демоданные используют устойчивые `demo-...`. Сущности содержат версию для оптимистической блокировки и временные метки. У старых записей временные метки могут быть пустыми.

Уникальны названия тем, адреса источников, синоним в пределах темы, тип условия в пределах утверждения, связь тем одного типа и пара источник–позиция в пределах утверждения. Числовые границы включительные; допускается одна открытая граница. Ветер измеряется в м/с, волны в м, температура в °C. Противоречивые категориальные условия одной группы в одной записи запрещены.

Схема пока обновляется через Hibernate `update`. Для старой PostgreSQL автоматически заменяется только исходное ограничение с шестью типами условий; остальные пользовательские ограничения не затрагиваются. Дополнительно создаётся индекс `statement_references(topic_id)`, на который опирается поиск по теме: Hibernate ведёт таблицу связей сам, но вторичный индекс на ней объявить не умеет. Общий механизм версионированных миграций пока не введён.

## Поиск

Нормализация: Unicode NFKC, нижний регистр, ё→е, совпадения по целым словам и фразам. Словарь категорий и условий находится в [search-dictionary.properties](src/main/resources/search-dictionary.properties); названия и синонимы тем — в БД.

Структурированный поиск принимает несколько категорий. Явные фильтры имеют приоритет над распознанным текстом. Можно искать с пустым вопросом, выбрав тему. Числа распознаются в выражениях вроде «ветер 5 м/с», «температура воды 18 °C», «волны 0,5 м». Прямое отрицание словарной фразы, например «не новичок», исключает соответствующее ограничение; это не полноценный анализ русского языка.

Ищутся `VERIFIED` и, по запросу, `DEMO` по основной теме, ссылкам утверждения и соседним темам. При явно выбранном виде спорта утверждения других видов спорта не подмешиваются. Связи дают поисковую область, а не доказательство или автоматическое наследование правил. Несколько распознанных видов спорта требуют уточнения; сравнение пока не реализовано.

Приоритет: основная тема → дополнительная тема → соседняя тема; затем проверенный статус, совпавшие условия и дополнительные темы запроса. Равные результаты упорядочены по ID. Возможная опечатка предлагается отдельной подсказкой, тема не заменяется автоматически.

Применимость результата:

- `MATCHED`: все сохранённые условия сопоставлены с контекстом пользователя.
- `CONDITIONAL`: часть ограничений не названа; они остаются в карточке.
- `UNSPECIFIED`: у утверждения нет сохранённых условий; это не означает универсальность.

Явный конфликт с условием или выход из числового диапазона исключает запись. Кандидаты отбираются, ранжируются и постранично выбираются в БД: база возвращает идентификаторы нужной страницы и общее число подходящих записей, а полные объекты читаются только для этих идентификаторов. Проверка совместимости условий и ранжирование в памяти больше не выполняются; порядок выдачи прежний: основная тема, затем ссылка на тему, затем статус, число совпавших условий, число связанных тем и идентификатор. Размер страницы — от 1 до 50.

## API

| Метод и адрес | Действие |
| --- | --- |
| `GET /api/dashboard`, `GET /api/catalog` | Сводка и справочники |
| `POST /api/search` | Поиск с фильтрами и пагинацией |
| `GET /api/statements?status=&topicId=&q=&page=0&size=20` | Список для редактора |
| `GET /api/statements/{id}` | Карточка и история проверок |
| `POST /api/statements`, `PUT /api/statements/{id}` | Создание и правка |
| `POST /api/statements/{id}/review` | Решение проверки |
| `POST /api/topics`, `PUT /api/topics/{id}` | Темы и синонимы |
| `POST /api/sources`, `PUT /api/sources/{id}` | Источники |
| `GET /api/relations`, `POST /api/relations` | Связи между темами |

Тела запросов — JSON. Для правки и проверки утверждения обязательна `version` из последней карточки. Ошибка возвращает `message` и `fieldErrors`; неправильный ввод — HTTP 400, отсутствующая запись — 404, конфликт данных или версии — 409.

Пример поиска:

```json
{"question":"Снаряжение для SUP","topicId":null,"categories":["EQUIPMENT"],"conditions":["BEGINNER"],"numericConditions":{"WIND_SPEED":5},"includeDemo":true,"page":0,"size":10}
```

## Данные и настройки

Загрузчик добавляет 8 тем, 31 синоним, 6 связей, 18 утверждений, 13 условий и 18 подтверждений из [demo-statements.tsv](src/main/resources/demo-statements.tsv). Все утверждения имеют статус `DEMO`; это учебные примеры без внешней проверки. Последовательный повторный запуск не изменяет существующие записи. Загрузка отделена от консоли.

| Настройка в `.env` | Значение по умолчанию |
| --- | --- |
| `DB_HOST`, `DB_PORT`, `DB_NAME` | 127.0.0.1, 5433, water_knowledge |
| `DB_USERNAME`, `DB_PASSWORD` | water_knowledge, root |

| `DEMO_INCLUDE` | true, только для консоли |
| `APP_MODE`, `CONSOLE_ENABLED` | servlet, false; для консоли используйте профиль console |

## Проверки

`mvn verify` запускает тесты на H2: прежние сценарии консоли, поиск по связям и числам, применимость, проверка/история, редактирование и версии, SQL-ограничения, а также полный сценарий через HTTP. H2 используется только в тестах и не входит в рабочий jar.

Тесты хранения можно запустить на **отдельной пустой тестовой PostgreSQL**:

```powershell
$env:TEST_DB_URL = 'jdbc:postgresql://localhost:5433/water_knowledge_test'
$env:TEST_DB_USERNAME = 'water_knowledge'
$env:TEST_DB_PASSWORD = 'root'
mvn test
```

Создайте `water_knowledge_test` заранее. Тестовый профиль использует **create-drop**: рабочую базу указывать нельзя. HTTP-тесты используют отдельную H2 независимо от TEST_DB_URL.

Интеграции с Go-Spot, загрузки документов, автоматической проверки, авторизации и полноценного понимания свободного языка пока нет.
